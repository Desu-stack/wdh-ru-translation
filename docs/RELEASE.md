# Публикация релиза

## Через сайт GitHub

1. Создай репозиторий `wdh-ru-translation` (Public).
2. Загрузи файлы репозитория.
3. Открой **Releases** → **Draft a new release**.
4. Укажи тег, например `v1.1.0`.
5. Прикрепи `WDH_RU_Patcher_v1.1.0.zip` и `SHA256SUMS.txt`.
6. Опубликуй релиз.

Архив для релиза собирается по инструкции [BUILD.md](BUILD.md). В репозиторий не нужно коммитить `dist/`, `build/`, `_internal/` и готовый `.exe` — они должны лежать только в релизе.

## Через GitHub Actions

Workflow `.github/workflows/release.yml` собирает onedir-версию и прикрепляет zip к релизу при пуше тега:

```powershell
git tag v1.1.0
git push origin v1.1.0
```

После этого открой вкладку **Actions**, дождись сборки и проверь черновик релиза. Если сборка использует подпись, сначала настрой SignPath по [SIGNING.md](SIGNING.md).

## Что проверить перед публикацией

- `WDH_RU_Patcher.exe` запускается из распакованного архива на `C:`.
- `--check` на чистой копии показывает `clean`.
- Установка и удаление проходят, `WDH_RU_Backup` исчезает.
- `SHA256SUMS.txt` совпадает с содержимым архива.
- В архиве нет файлов игры, `resS` целиком, `_internal` из чужой сборки и локальных бэкапов.
